1. 핵심 판단
이 문서는 이미 AI 에이전트를 핵심 서비스로 제안한다. 추가로 필요한 작업은 고객 시나리오를 입력 정보 → 
판단 → 도구 호출 → 고객 확인 → 실행 결과 확인 → 계획 수정으로 구체화하는 것이다.
가장 적합한 서비스 정의는 다음과 같다.
고객이 확인한 생애 변화와 금융 목표를 바탕으로, 필요한 일을 순서대로 준비하고 진행 상태를 추
적하며 상황이 바뀌면 계획을 수정하는 금융 준비 에이전트.
고객에게는 생활 준비의 부담과 기한 누락을 줄이고, 은행에는 반복 상담과 서류 보완 비용을 줄이면서 거래 관
계가 이어지는지를 검증하는 구조다. 추천 상품 수보다 실제 완료한 고객 과제를 중심에 둬야 한다.
공모전 대표 시연은 전역 후 복학·독립 자금 준비를 추천한다. 첫 수입 관리보다 수령·지출 시점의 충돌이 명확
하고, 주거대출 전 과정보다 초기 구현 범위를 제한하기 쉽다. 이는 PDF가 제시한 네 구간 중 시연 적합성에 관
한 판단이며, 실제 시장 규모나 수익성이 가장 크다는 실증 결론은 아니다.

3. 구체적으로 AI를 활용할 수 있는 일곱 지점
3.1 생애 변화 확인
• 입력: 생년월일, 고객이 등록한 입학·취업·입대·이사 일정, 내부 금융 사건, 동의 범위의 외부 거래.
• 처리: 거래 분류나 반복성 탐지로 확인 후보를 만들고, AI는 이전 계획과 대화 맥락을 참고하여 필요한 질문을
 고른다.
• 예시: 반복 입금을 발견하면 “새로 시작한 아르바이트 수입인가요?”라고 확인한다. 고객이 용돈이라고 답하면
 급여 준비 과제를 만들지 않는다.
• 산출물: 고객이 확인한 사건, 예정일, 근거, 아직 모르는 항목.
• 효과: 잘못된 상품 제안과 불필요한 질문 감소.
• 구현 판단: 생일·만기 알림은 규칙으로 충분하다. AI의 가치는 여러 신호와 과거 목표가 충돌할 때 무엇을 추
가 확인할지 판단하는 데 있다.

3.2 고객별 준비 계획 수립
• 입력: 확인된 사건, 보유 금융 수단, 지출 기한, 자금 상황, 고객의 우선순위.
• 처리: 해야 할 일을 생성하고 선행 조건을 연결한다. 이미 완료한 일과 필요 없는 가입을 제외한다.
• 예시: “기존 계좌 확인 → 급여계좌 정보 준비 → 첫 입금 확인 → 납입일 조정”을 만들고, 체크카드가 충분하
면 새 카드 발급은 제외한다.
• 산출물: 과제·기한·선행 조건·담당 주체·필요한 확인·완료 기준을 가진 준비 목록.
• 효과: 상품별 탐색과 반복 설명 감소.
• 구현 판단: 공통 업무 순서는 승인된 템플릿을 사용하고, AI는 개인 사정에 따른 과제 선택·순서 조정·예외 설
명을 맡는다.
3.3 정책·상품 조건 조사와 검토
• 입력: 승인된 상품 설명서, 공식 정책 공고, 모집 일정, 고객이 제공한 자격 정보.
• 처리: 최신 승인 자료를 검색하고 해당 조건을 규칙 검사로 확인한다. 근거가 부족하면 가입 가능 확정 대신
추가 확인 또는 상담 상태로 둔다.
• 예시: “연령 요건 확인 / 소득 확인 자료 부족 / 모집 일정 재확인 필요”처럼 항목별로 구분한다.
• 산출물: 검토 후보, 제외 사유, 부족한 정보, 출처·기준일.
• 효과: 오래된 상품 안내와 불필요한 신청 감소.
• 구현 판단: 검색으로 찾은 문장을 그대로 판정에 쓰지 않는다. 운영자가 승인한 조건 버전과 적용일을 사용한
다. 일반 웹페이지의 지시는 에이전트 명령으로 취급하지 않는다.
3.4 현금흐름 검토와 계획 수정
• 입력: 현재 사용 가능한 잔액, 확정·예상 수입, 날짜별 지출, 비상금 기준, 계약 조건.
• 처리: 계산 도구로 날짜별 잔액과 부족 구간을 계산한다. AI는 원인과 선택지를 설명하고 고객의 선택에 따라
계획을 다시 만든다.
• 예시: “등록금 납부일이 지원금 수령 예정일보다 빠릅니다. 현재 확정 자금만으로 준비 가능한 안을 다시 계
산했습니다.”
• 산출물: 날짜별 자금표, 부족 금액, 변경 전후 비교, 확인이 필요한 가정.
• 효과: 납부 시점의 자금 부족과 무리한 저축 계획 감소.
• 구현 판단: 금액 계산은 코드·계산 엔진으로 수행한다. 불확실한 수입은 확정 수입과 분리하고 지연 시나리오
도 계산한다.

3.5 신청·상담 준비와 결과 추적
• 입력: 고객이 선택한 과제, 필요한 서류, 신청 결과, 상담 가능 정보.
• 처리: 서류 항목을 추출하여 누락·불일치를 표시하고, 가능한 연동 도구나 기존 업무 화면으로 연결한다. 결과
가 돌아오면 상태를 갱신한다.
• 예시: 주거 상담 전에 고객이 확인한 소득·보증금·잔금일·부족 서류를 요약하고, 담당자가 검토한 뒤 상담에 활
용한다.
• 산출물: 신청 초안, 서류 준비 목록, 상담 요약, 처리 결과와 다음 과제.
• 효과: 재방문·재제출·인계 시 반복 설명 감소.
• 구현 판단: 공식 연동이 없는 기관은 체크리스트·링크·고객 완료 확인으로 처리한다. 외부 신청서를 준비했다
는 사실과 접수·승인을 구분한다.
3.6 장기 기억과 다음 전환 연결
• 입력: 고객이 확인한 목표·제약·선호, 이전 계획과 실제 수행 결과.
• 처리: 다음 의사결정에 필요한 사실을 선택적으로 기억하고, 현재 계획과 충돌하면 고객에게 재확인한다.
• 예시: 과거 “다음 학기 복학 예정”을 기억하되, 전역 준비 때 복학 여부와 등록금 기한을 다시 확인한다.
• 산출물: 고객이 열람·정정할 수 있는 계획 이력과 금융 여정 요약.
• 효과: 다음 전환에서의 질문 수 감소와 계획의 연속성.
• 구현 판단: 모든 대화를 영구 저장하는 방식보다 내용·출처·확인일·유효기간·이용 목적·동의 상태를 가진 기록
이 적합하다. 고객 확인 사실, 거래 사실, 모델의 추정은 분리한다. 오래된 추정이 반복해서 사실로 복제되지 
않게 한다.
3.7 은행 내부 업무 지원
• 입력: 공식 정책 변경, 상담 기록, 중단·보완 사유, 과제별 처리 시간.
• 처리: 정책 변경의 영향 대상을 찾고, 상담에 필요한 맥락을 요약하고, 업무 중단 원인과 개선안을 제안한다.
• 예시: 모집 일정 변경을 발견하면 영향을 받는 준비 과제와 안내 초안을 만들고 운영자 검토 뒤 반영한다.
• 산출물: 정책 변경 비교표, 상담 인계 자료, 병목 분석, 개선안.
• 효과: 자료 검색·안내 수정·중복 상담의 처리 시간 감소 가능성.
• 구현 판단: 고객 안내 자동 배포나 상품 자격 규칙 변경은 검토 절차를 거친다. 상담 요약으로 원문과 근거 문
서가 대체되지 않게 한다.

10. 단계별 도입과 미래 확장
공모전 최소 시연
전역·복학·독립의 가상 고객 한 명을 대상으로, 목적 확인·모의 조회·날짜별 계산·과제 생성·일정 변경 후 재계획
을 구현한다. 모든 상품을 통합하거나 실제 금융계약을 수행할 필요는 없다. 핵심은 계획이 바뀔 때의 행동과
검증 가능한 결과다.
초기 실증
성인 준비 또는 전역 준비의 제한된 범위에서 읽기·계획·서류 준비·직원 인계부터 운영한다. 기존 인증·신청 경
로를 활용하고, 상담 지원 효과와 완료율을 측정한다. 고객용 기능과 직원용 요약을 같은 진행 상태에 연결해야
 중복 설명을 줄일 수 있다.
확장
첫 수입의 변동성 대응, 취업·독립의 복합 준비, 고객이 정정 가능한 장기 기억을 순차적으로 추가한다. 다기관
실행은 각 기관의 연동·허용 범위·위임 구조가 확보된 업무부터 적용한다.
미래 방안
• 권리 행사와 생활 준비 연결: 취업·소득 변화 뒤 기존 대출 조건 검토 등 고객에게 유리한 권리 행사를 생애 
계획과 연결한다. 금리인하요구 대행 자체는 이미 운영 사례가 있으므로 새로운 발명으로 주장하지 않는다.
• 다기관 준비 조정: 은행·학교·공공기관의 준비 상태를 연결하여 제출 기한과 서류 재사용을 관리한다. 실제 대
리 제출은 기관별 허용과 연동 확보를 전제로 한다.
• 계획의 지속 수정: 이직·휴학·소득 중단 등 목표 변경을 반영해 과도한 납입이나 납부 공백을 줄이는 방향으로
 확장한다.
• 고객이 통제하는 금융 이력: 확인 가능한 거래·목표·완료 기록을 고객이 가져갈 수 있게 하고, 서비스의 경쟁
력은 그 이후의 정확한 관리에서 확보한다.

11. 공모전 제안서에 추가할 내용
